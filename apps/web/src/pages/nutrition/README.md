# Nutrition pages — assumptions & deviations

These pages code strictly against the shared-UI contract (`GlassCard`, `RingProgress`, `MetricCard`, `Chip`, `Input`, `Skeleton`, `EmptyState`, `ErrorState`, `AppHeader`, `useToast` from `@/components/ui/Toast`) which was being built concurrently; assumptions made where the contract was underspecified: `useToast()` returns `{ show(message: string) }`, components are **named** exports one-per-file, and `AppHeader`'s `back` prop is a boolean. Query keys follow the mandated map; two resources without mandated keys use `['vision', jobId]` (photo-analysis poll) and `['recipes', id]`. Response envelopes are normalised defensively (`/me`, `/workouts/today`, `/foods`, `/recommendations/meals`, `/meal-photos` may return the entity directly or wrapped). Deviations from the brief: photo upload shows an **indeterminate** progress bar (fetch-based `api()` cannot report upload progress and raw `fetch`/XHR is disallowed); `RecipeDetail` logs a meal whose grams are estimated from the recipe's total ingredient grams per serving (kcal/macros are exact `perServing × servings`) with the meal type inferred from time of day; the Nutrition date selector uses prev/next chevrons + "Today" (per brief) instead of the mock's calendar strip, and the mock's weekly calorie trend bars were kept using `['nutrition','trends','7d']`. Shared small helpers (dates, idempotency keys, response normalisers) and the water/macro/sparkline cards live in `src/pages/dashboard/` and are reused here; `FoodSearchSheet`/`GramsStepper` are exported from `Nutrition.tsx` for reuse by `AnalysisResults.tsx`. All kcal/macro math is deterministic client-side scaling from per-100g / per-gram values — never model-estimated — and photo analysis never auto-commits.
