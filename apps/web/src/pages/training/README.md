# Training / Progress / Coach pages — assumptions & deviations

These pages (WorkoutLibrary, WorkoutDetail, Progress, LogWeight, Coach) consume the shared UI kit in `src/components/ui/` exactly as contracted (GlassCard, RingProgress, MetricCard, Chip, PrimaryButton, SecondaryButton, Input, Skeleton, EmptyState, ErrorState, AppHeader, `useToast()` — assumed shape `useToast().show(message)` and `AppHeader({ title?, back?: boolean, right? })`), and normalise list endpoints defensively (accepting either `T[]` or `{ items: T[] }`; `404` from `/plans/current` and `/workouts/today` is treated as "no data" rather than an error). Deviations from the mocks: the weekly strip cannot mark *past* days of the current week as completed because the API exposes only today's session state, so past/future days render as neutral date chips (rest days get a lounge icon) and the "4/7 Completed" label becomes "N training days"; the workout hero and exercise thumbnails use gradient/icon media placeholders since seeded media URLs are placeholders; `WorkoutDetail` always renders **today's** session per the brief even when the `:id` param mismatches; the Progress range selector uses the API's `7d/30d/90d` instead of the mock's `1W/1M/6M`; the mock's "1W/1M/6M" achievements copy is driven by real `achievementDefinitions`; LogWeight is a full page styled like the mock's bottom sheet, converts lb→kg at the edge only (canonical kg submitted, rounded to 0.1), and shows the clamp/targets-recomputed advisory from the response when present; Coach renders the full shared `WELLNESS_DISCLAIMER` (the mock shows a shortened line), uses a kebab menu (instead of long-press) for "Report response", and blocks (SAFETY_INPUT/crisis/credits/rate-limit) render as calm sea-green supportive frames — never error-red.
